## 1. Наименование и назначение

**Атлас-LLM** — текстовая LLM-система-эксперт по технологиям клонирования и
синтеза голоса (TTS/VC/SVC/SVS), отвечающая строго по корпусу «Технического
атласа 2026» с RAG-подтверждением, честными отказами вне корпуса и съёмным
LoRA-адаптером поверх базовой модели.

**Целевая аудитория:** инженер/исследователь speech-tech, контент-студии,
аудиторы пайплайнов голоса.

**Чем система НЕ является (фиксация против галлюцинаций коллег #1/#2):**
не голосовой ассистент, не STT/TTS-конвейер, не «поли-матричный роутер».
Голос — домен знаний, интерфейс — текст (CLI сейчас, HTTP-обёртка в планах).

## 2. Пользовательские сценарии

1. Спросить «чем SVC отличается от SVS» → получить ответ с указанием глав-источников (реализовано: `inference/chat_cli.py --dry`).
2. Спросить о том, чего нет в корпусе → получить честный отказ/маркер неопределённости, а не выдумку (частично: 1/9 в текущем eval; цель — стабильность).
3. Дообучить модель на новой главе атласа → `build_dataset.py` + `train_lora.py` одной командой, детерминированно (реализовано, seed 42).
4. Оценить качество адаптера гейтом метрик до публикации (реализовано: `evaluation/eval_qa.py`).
5. Проверить, что ответ подкреплён корпусом, а не фантазией модели (в плане: LLM-as-a-Judge, §EVALUATION_PLAN).

## 3. Функциональные требования

**Реализовано (ссылки на код):**

- FR-1 Корпус знаний: 20 глав `data/atlas/*.md`, единственный источник истины; правки аудита (глава 20, C01–C20).
- FR-2 Датасет: куратор 142 пары + автоглоссарий → валидация (кириллица, длина, дедуп) → сплит 154/9, seed 42 (`data/build_dataset.py`).
- FR-3 RAG: TF-IDF, char_wb n-граммы, офлайн, k настраиваемое (`inference/retriever.py`).
- FR-4 Обучение: LoRA r=16/alpha=32/dropout 0.05, 7 target-модулей, masked loss только на ответе, чанкинг CE по 64 токена, gradient checkpointing use_reentrant=False (`training/train_lora.py`).
- FR-5 Инференс: три режима — dry-RAG / база+RAG / база+адаптер+RAG (`inference/chat_cli.py`).
- FR-6 Гейт качества: token_f1, keyword_coverage, honest_uncertainty + отчёты JSON (`evaluation/eval_qa.py`).
- FR-7 Слияние адаптера → автономная модель (`training/merge_lora.py`).

**Новые требования этого ТЗ (в план, см. ROADMAP_v2):**

- FR-8 HTTP-инференс: `inference/api.py` (FastAPI), контракты `/ask` (вопрос → ответ+источники+маркер уверенности), `/health`; лимиты размера входа и таймауты (за #9, #12).
- FR-9 Judge-контур: автоматическая проверка «ответ подкреплён контекстом?» на eval-наборе, метрика audit_pass_rate (порог калибруется, стартовая цель ≥ 0.95 — за #12, с оговоркой о калибровке).
- FR-10 Память знаний: при добавлении главы — только дифф-step (пересборка датасета + короткий догон), без переобучения с нуля; контроль катастрофического забывания replay-буфером ≥ 10% старых пар (за #11, адаптировано).

## 4. Нефункциональные требования

- **NFR-1 Воспроизводимость (за #8):** пины версий в `requirements-ml.txt` (сейчас torch>=2.2, transformers>=4.44 — без пинов, что подтверждено аудитом); фиксированный seed во всех компонентах; sha256 датасета и адаптера в отчёте обучения; лог прогона сохраняется в репо.
- **NFR-2 Ресурсы:** полный прогон укладывается в 4 ГБ RAM / 2 ядра CPU (~85 мин, проверено: `training_report.json`, elapsed 5098.7 c) или ~25–40 мин на RTX 3060/T4.
- **NFR-3 Безопасность:** отсутствие секретов в коде и логах; токены GitHub — только в командной строке одноразово; входные лимиты на файлы/запросы (за #9).
- **NFR-4 Честность порогов:** аудио-пороги атласа (SIM ≥ 0.80, WER ≤ 5%, UTMOS) не применяются к текстовым метрикам; текстовые пороги только через калибровку (глава 20).
- **NFR-5 Детерминизм:** повторный прогон с тем же seed и версиями даёт вал-лосс с точностью до кросс-платформенного шума; proof-лоссы фиксированы (3.7432/3.6326/4.2723/3.3418, val 3.5158).

## 6. Эволюция к ролям (за #6, #11 — как план, не факт)

Текущая монолитная CLI-логика при росте распределяется по ролям с явными
контрактами (все — обычные функции/сервисы, без «агентных» свобод):

| Роль | Ответственность | Реализация сейчас |
|---|---|---|
| Knowledge | ответ по корпусу с источниками | retriever + chat_cli |
| Quality Gate | метрики, вердикт годности | eval_qa |
| Compliance | маркировка синтетики, source_immutable; лицензии — информационно | docs/THREAT_MODEL.md T3 (эхо-политика) |
| Judge | «ответ подкреплён контекстом?» | план (EVALUATION_PLAN §5) |
| Adaptation | новые главы, догон, забывание | план (FR-10) |

## 7. Вне scope (осознанные отказы)

- **Выдача синтетики за подлинную запись** (обман слушателя — единственная
  формулировка вреда; эхо-политика T3 THREAT_MODEL, политика владельца из
  материалов VFE). Копирование и исполнение чужого тембра сами по себе —
  НЕ запрещены и НЕ требуют разрешительных процедур: «песни поют как раз
  для того, чтобы их исполняли»; жёсткий гейт один — неприкосновенность
  исходника, маркировка синтетики обязательна.
- Автономные действия от имени пользователя (за #9).
- Заявления об экспертности в медицине/праве/финансах.
- K8s/Helm/мультитенантность — до появления второго пользователя (SYNTHESIS §6).
- Возвращение блокирующих consent/license/AES/RBAC/C2PA-гейтов — отвергнуто
  владельцем (казуистика); см. lineage VFE: 0.4/v1.0 → убраны в 0.5.0.
