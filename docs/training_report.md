# Отчёт об обучении Атлас-LLM

Все цифры ниже — реальные логи прогонов этого репозитория, без прикрас
(дисциплина главы 11 и главы 20 атласа: отчёт ≠ обещание).

## Прогон 1 — smoke пайплайна (tiny-gpt2, CPU)

- Конфиг: `training/configs/smoke-tiny.yaml` (sshleifer/tiny-gpt2, 0.1M параметров)
- Задача: проверить код обучения, а не качество.
- Результат: 39 шагов, 43 с, лосс ≈ 10.82 (плоский — ожидаемо:
  у модели hidden=2, LoRA 0.06% параметров, 1 эпоха).
- Вывод: **пайплайн исправен** — датасет, маска лосса, оптимизатор,
  сохранение адаптера и отчёта работают end-to-end.

## Прогон 2 — proof на реальной модели (Qwen2.5-0.5B-Instruct, CPU)

- Конфиг: `training/configs/cpu-proof-qwen.yaml`, `--limit 4`
- 4 шага, 12 с, лосс 3.72 → 3.53, val 3.61.
- Вывод: реальная модель грузится, градиенты текут, адаптер сохраняется.

## Прогон 3 — demo-обучение (Qwen2.5-0.5B-Instruct, CPU) — артефакт в репо

- Конфиг: `training/configs/cpu-demo-qwen.yaml`, `--limit 50`
- Условия: bf16-веса на CPU (4 ГБ RAM!), max_len 448, batch 1, grad_accum 2,
  LoRA r=16 на всех проекциях → 8.80M обучаемых параметров (1.75%).
- Результат: 25 оптимизаторных шагов за 173 с.
  - train loss: 3.88 → 3.13 → 2.98 (шумно по микробатчам, тренд вниз)
  - val_loss: 3.26
- Проверка генерации (chat_cli + адаптер + RAG): модель выдаёт связный
  русский текст по формату «Вопрос/Ответ», но семантика после 25 шагов
  слабая — это ДЕМО-адаптер, а не готовая модель.
- Инженерные находки (задокументированы для будущих прогонов):
  - Кириллица в gpt2-BPE раздувает текст до 3–4 токенов/символ:
    в smoke-конфиге max_len должен покрывать ответ целиком;
    в тренере реализована обрезка промпта слева с сохранением ответа.
  - На 4 ГБ RAM batch_size ≥ 2 при seq 448–512 убивает процесс (OOM,
    exit 137): CPU-прогоны — batch 1 + bf16-веса.
  - `huggingface_hub`-загрузка весов может залипать на лимитах:
    прямое скачивание через curl в `models/_base/` решает это.

## Оценка RAG (без генерации)

`python evaluation/eval_qa.py --retrieval-only --max-samples 9`:
mean_rag_coverage = 0.49 по ключевым словам эталона в топ-1 чанке.
TF-IDF по char_wb 3–5 граммам находит релевантную главу устойчиво;
покрытие «всего ответа» одним чанком естественно частичное.

## Прогон 4 — ПОЛНОЕ обучение (Qwen2.5-0.5B-Instruct, CPU-порт, 4 эпохи) — артефакт в репо

- Конфиг: `training/configs/qwen2.5-0.5b-ru-cpu.yaml` — CPU-порт канонического
  `qwen2.5-0.5b-ru.yaml`. Семантика обучения сохранена 1:1: весь датасет 154/9,
  LoRA r=16/alpha=32 на всех 7 проекциях, 4 эпохи, lr 2e-4, cosine, warmup 6%.
- Аппаратные отличия: batch 1 + grad_accum 16 (эффективный батч 16 = 8×2 GPU-варианта),
  веса в bf16, max_len 640 (≥ p100=601 токен по замеру длин пар).
- Ход: 40 оптимизаторных шагов за 5098.7 с (~85 мин, 2 CPU-ядра, RSS плато ~2.9 ГБ).
  - train loss (running по шагам): 3.61 → 1.38; val_loss по эпохам:
    **3.106 → 2.901 → 2.831 → 2.824** (монотонное улучшение).
- Инженерный итог (код в `training/train_lora.py`, работает и на GPU):
  - `masked_lm_loss`: lm_head только на позициях ответа — полные [seq × 152k] логиты
    не материализуются; эквивалентно CE с ignore_index=-100;
  - чанкинг lm_head+CE по 64 токена через `checkpoint(use_reentrant=False)`:
    в памяти живёт логит-блок одного чанка (~140 МБ) независимо от длины ответа;
  - gradient checkpointing строго `use_reentrant=False` (reentrant рвёт
    градиенты LoRA на замороженных эмбеддингах);
  - malloc-гигиена: `MALLOC_ARENA_MAX=2`, `MALLOC_MMAP_THRESHOLD_=131072`.
- Детерминизм: после рестарта песочницы прогон восстановлен с нуля и воспроизвёл
  все чекпойнт-значения лосса побайтово (3.2098@5, 1.9372@10, …, 1.3778@40)
  при seed 42 — воспроизводимость пайплайна подтверждена дважды.

## Оценка гейта полного адаптера (held-out val, 9 вопросов, генерация)

`python evaluation/eval_qa.py --adapter models/atlas-qwen-0.5b --max-samples 9
--max-new-tokens 220` → `evaluation/report_full.json`:

- mean_token_f1 = **0.205**, mean_keyword_coverage = **0.177**,
  honest_uncertainty_rate = 0.11, elapsed 210.6 с (CPU, greedy).
- Для масштаба: RAG-only покрытие (без генерации) — 0.49 по тем же 9 вопросам.
- Чтение цифр: 0.5B-модель после 4 CPU-эпох на 163 парах устойчиво попадает в
  терминологию и факты атласа (пороги, названия инструментов, различия слоёв),
  но перефразирует свободно — token_f1 на коротких ответах это честно штрафует.
  Пороги атласа (SIM ≥ 0.80 и т.п.) — для аудио-копий; текстовые пороги
  калибруются по главе 20, а не постулируются.

### Демо-генерации (адаптер + RAG, greedy)

| Вопрос | Ответ Атлас-LLM | Источники |
|---|---|---|
| чем SVC отличается от SVS? | «SVC → текст → поёт как ты, без персонального редактора. Сравнение с SVS: SVS → готовый исполнитель, с ручной редакцией» | 02_taxonomy, 07, 08 |
| какие пороги SIM считаются хорошими? | «SIM ≥ 0.85 — «высоко»; отсев SIM ≤ 0.80 — «низко»; UTMOS ≤ 3.5 — «маленький» — это фундаментальная граница» | 09_layer_f_codecs, 20_audit_corrections |
| какие вокодеры подходят для пения? | «BigVGAN, BigVGAN-v2, Vocos, F5-TTS, F5-TTS-семейство, Whisper» | 09_layer_f_codecs, 01_four_layers |

Замечания честности: пороги SIM/UTMOS и BigVGAN/Vocos — факты корпуса;
упоминание F5-TTS в ряду вокодеров — смешение соседних понятий главы 09
(TTS-модель vs вокодер), ожидаемый артефакт малой модели. Ответы terse:
компактные обучающие пары → компактные ответы.

## Как запустить полное обучение

```bash
# Вариант 1: CPU (проверено в этом репозитории, ~85 мин на 2 ядрах / 4 ГБ RAM)
pip install -r requirements.txt -r requirements-ml.txt
python data/build_dataset.py
python training/train_lora.py --config training/configs/qwen2.5-0.5b-ru-cpu.yaml

# Вариант 2: RTX 3060 12 ГБ / Colab T4 (~25-40 мин)
python training/train_lora.py --config training/configs/qwen2.5-0.5b-ru.yaml

# Оценка гейта
python evaluation/eval_qa.py --adapter models/atlas-qwen-0.5b --max-samples 9
```
