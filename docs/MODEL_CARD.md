# Model Card · atlas-qwen-0.5b (v2)

**Дата:** 2026-11-04 · **Линия:** волна «Гибрид» ч.4 · Адаптер v2 заменяет v1
(коммит `908f578`, 2026-10-27).

## 1. Идентификация

| Поле | v1 (старый) | v2 (текущий) |
|---|---|---|
| Базовая модель | Qwen2.5-0.5B-Instruct (Apache-2.0) | та же |
| Метод | LoRA (PEFT 0.21.2), r=16, alpha=32, 7 модулей | та же |
| Обучаемых параметров | 8.80M (1.75%) | те же |
| Данные | 154 train / 9 val (случайный сплит) | **353 train / 30 val (сплит по главам, без близнецов)** |
| Режим | 4 эпохи, 40 шагов | 3 эпохи, 69 шагов, batch 1 × accum 16, lr 2e-4 cosine, CPU bf16-веса |
| Время | 5099 c (~85 мин одним прогоном) | **4860 c чистого времени, 11 окон по ≤7 мин с чекпоинт-резюмом** (`training/train_lora.py --resume --max-minutes`) |

## 2. Результаты обучения (v2)

- val_loss: 2.9013 → 2.7806 → **2.7691** (монотонно, 3 эпохи).
- Прямое сравнение val_loss с v1 (2.824) некорректно: другие val-наборы (30 vs 9).
- Детерминизм: перестановка эпохи = seed×1000+epoch; резюм продолжается
  байт-в-байт (проверено на окнах: gstep 2→4, потом 6→69 без пропусков).

## 3. Честный A/B на ОДНОМ вале-30, тот же RAG-контекст (главное)

| Метрика (генерация, n=30) | v1 (163 пары) | v2 (383 пары) | Вердикт |
|---|---|---|---|
| token_f1 | **0.211** | 0.179 | **РЕГРЕССИЯ −15%** |
| keyword_coverage | 0.229 | 0.232 | на равных |
| honest_uncertainty | 0.0 | 0.0 | маркер честности не срабатывает ни у кого |

Отчёты: `evaluation/report_v1_on_val30.json` (v1), `evaluation/report_full.json` (v2).

**Разбор без прикрас:** расширение корпуса 163→383 в текущем виде (авто-QA по
таблицам = 62% корпуса) улучшило ретривер (покрытие контекста 0.49 → 0.833) и
вписываемость (val_loss), но НЕ улучшило генерацию — F1 упал. Лучшие ответы v2 —
табличные факты (нейрокодеки 0.85); худшие — процедурные «рецепты» (0.0).
Причина: стиль авто-таблиц доминирует и смещает адаптер; LoRA-ёмкость та же.

**Лечение (корпус v3, следующая волна):** кэп доли table_qa (~30%), добавить
парафразы и процедурные/рецептные QA с эталонами-псевдокодом, взвешенное
сэмплирование; проверка ТОМ ЖЕ вале-30 и том же протоколе A/B. Маркер честности
(«не подтверждено») — на семантическую замену (EVALUATION_PLAN §5), regex не
срабатывает.

## 4. Что улучшилось объективно (вне генерации)

- RAG-покрытие контекста: 0.49 (top1, val-9) → **0.833** (union top-3, val-30):
  `evaluation/report_retrieval.json`.
- Сплит по главам: утечка близнецов train/val устранена (DATA_CARD §0).
- Инфраструктура: чанкуемое обучение с резюмом — прогон переживает любые
  перезапуски среды; это сняло главный операционный риск CPU-линии.

## 5. Предназначение и границы

- ✅ Ответы по терминологии/порогам/законам атласа с RAG-источниками; таблицы корпуса.
- ✅ Воспроизводимый пайплайн «корпус → датасет → LoRA → гейт» на CPU 4 ГБ.
- ❌ Не финальный продукт: F1 < 0.25; факты вне корпуса галлюцинируются;
  honest-маркер не работает (regex); n=30 всё ещё мало для статистики.
- ❌ Не синтезирует голос — текстовый эксперт (SYNTHESIS §2 #1).

## 6. Воспроизведение

```bash
pip install -r requirements-ml.txt   # пины: torch 2.14.1+cpu, transformers 5.20.2, peft 0.21.2
python training/train_lora.py --config training/configs/qwen2.5-0.5b-atlas-v2.yaml
# прерываемое обучение: те же + --resume --max-minutes 7 (окна; см. WORKS.md)
python evaluation/eval_qa.py --adapter models/atlas-qwen-0.5b \
    --base models/_base/Qwen2.5-0.5B-Instruct --max-samples 30 \
    --out evaluation/report_full.json
```
Внимание: стек пиннутый — на torch 2.15.0+cpu / transformers 5.21.0 трейнер
падает молча до первого шага (воспроизведено 2 раза 2026-10-28; виновник не
локализован, пин — рабочее решение).
