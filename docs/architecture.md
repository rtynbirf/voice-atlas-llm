# Архитектура Атлас-LLM

## Идея

Атлас (глава 1) утверждает: системы клонирования строятся на дизентанглменте —
разложении личности на независимые слои. Атлас-LLM применяет тот же принцип
к знаниям: **база (общий разум) остаётся нетронутой, домен надевается слоями**:

```
┌──────────────────────────────────────────────────────────┐
│  Слой 3. Генерация: базовая LLM + LoRA-адаптер (съёмный) │
├──────────────────────────────────────────────────────────┤
│  Слой 2. RAG: TF-IDF по корпусу атласа (20 глав)         │
├──────────────────────────────────────────────────────────┤
│  Слой 1. Датасет: кураторские QA + автоглоссарий         │
├──────────────────────────────────────────────────────────┤
│  Слой 0. Корпус: data/atlas/*.md (единственный источник) │
└──────────────────────────────────────────────────────────┘
```

Каждый слой обратим и заменяем: адаптер снимается, база знаний
дополняется главами, корпус версионируется в git. Это лестница глубины
из главы 10 атласа, применённая к самому атласу.

## Поток обучения

1. `data/build_dataset.py` — кураторские пары (`data/curated/qa_part*.jsonl`)
   + автогенерация из глоссария (глава 18) → валидация (кириллица, длина,
   дедупликация) → сплит train/val (~94/6).
2. `training/train_lora.py` — шаблон «Вопрос/Ответ» из `prompt_format.py`;
   лосс маскируется: модель учится только ответам. LoRA (r=16, alpha=32)
   на q/k/v/o/gate/up/down проекциях; fp32 на CPU, bf16 на GPU.
3. Проверка: `evaluation/eval_qa.py` на held-out val — token_f1,
   keyword_coverage, доля честных «не подтверждено».

## Поток инференса

1. Запрос → TF-IDF ретривер (char_wb 3–5 граммы) → топ-k чанков атласа.
2. Системный промпт + справка из атласа + вопрос → модель.
3. Ответ + список источников (какие главы использованы).

Такой «заземлённый» контекст снижает галлюцинации: модель может свериться
с корпусом, а пользователь видит, откуда взято утверждение.

## Почему не TRL/SFTTrainer

Ручной цикл обучения устойчив к смене версий transformers/peft и прозрачен:
виден каждый шаг, лосс, расписание. Для домена в ~200 пар этого достаточно;
апгрейд на TRL/Axolotl — задача дорожной карты, не блокер.

## Почему TF-IDF, а не эмбеддинги

Ступень RAG должна работать везде, включая CI без GPU и без сети:
TfidfVectorizer ставится из requirements.txt за секунды. Замена на
плотные эмбеддинги (multilingual MiniLM / bge-m3) — интерфейс
`TfidfRetriever.search(query, k)` остаётся тем же.
