# РАБОТАЕТ · Хроника только проверенного

> Директива владельца, 2026-10-27: «Введём правило в репе — ветка, куда ты
> будешь всегда фиксировать ТОЛЬКО ТО, ЧТО РЕАЛЬНО РАБОТАЕТ. И раскрывать
> весь алгоритм подробно, раскомментировав. От нулевой фазы (задумки
> человека) до получения (появления у него на ПК готового результата)».
>
> Этот документ — исполнение директивы. Правило жизни документа:
>
> 1. **Попадает только работающее.** Рецепт записывается после реального
>    выполнения, давшего проверяемый результат. Не «должно сработать»,
>    не «по документации так», а «выполнено — вот доказательство».
> 2. **Алгоритм раскрывается целиком.** Каждый шаг — с командой как она
>    реально выполнялась, с комментарием «почему именно так», со значениями,
>    которые реально получились, и с ловушками, которые реально сработали.
> 3. **Цепочка полная: Фаза 0 → Файл на ПК.** От задумки человека до
>    готового артефакта у владельца — ни одного разрыва между шагами.
> 4. **Каждая запись датирована** и имеет доказательство: коммит, отчёт,
>    измерение. Запись без доказательства не пишется.
>
> Терминология: «ветка» здесь — живой раздел репозитория на main
> (источник истины после вайпов — remote, отдельные git-ветки в этом
> проекте не выживают: песочница стирает локальные HEAD-ы, remote main — нет).

## Фаза 2. Корпус: скачивание 50/50 с Google Drive

**Работающий метод (единственный из проверенных):**

```bash
# gdown нестабилен — измерено (падает на больших файлах). Работает прямой URL:
curl -L -o "<файл>" "https://drive.usercontent.google.com/download?id=<DRIVE_ID>&export=download&confirm=t"
# confirm=t обходит страницу-предупреждение для больших файлов — проверено на всех 50.
```

**Алгоритм инжеста целиком** (`scripts/ruvson_ingest.py` → `ruvson_reingest.py`,
после вайпа восстановлен и отработал повторно):

1. Взять список (имя, drive_id) → скачать по URL-паттерну выше, 50/50 за 156 с.
2. **sha256 на приёме** каждого файла — до любых манипуляций. Это единственная
   защита от тихой порчи при передаче.
3. Определить реальный контейнер ffprobe'ом, НЕ расширением: измерены контейнеры,
   расходящиеся с расширением (mp4-контейнер в .mp3 и т.п.). Правило: **тип
   файла — только sniffing'ом ffprobe.**
4. Записать MANIFEST.jsonl: name, drive_id, size_bytes, sha256, container,
   has_video, audio_codec, duration_sec, audio_bitrate_kbps.
5. Дополнительно: HTML-детектор «скачалась ли страница вместо файла» —
   ловушка: первый детектор ловил байт `<` внутри бинарных данных mp4
   (трек 34 «Stay Young») и ложно ругался; рабочий детектор — по
   Content-Type + `<!doctype` / `<html` в первых байтах.

**Результат:** 50/50 файлов, 3.89 ГБ, sha256 в манифесте. Доказательство:
`data/ruvson/MANIFEST.jsonl`, `voice_data_raw/ruvson/reingest_report.json`, коммит b902a4a.

## Фаза 4. Каталог внешних следов: правила, которые сработали

**Метод верификации площадки — фиксируется честно, тремя уровнями:**

| Уровень | Что означает | Примеры (сработавшие) |
|---|---|---|
| прямая загрузка | страница скачана curl'ом из песочницы | Apple Music artist/1846472536; audset artist/96195; readdork |
| поисковая выдача | сущность видна в поиске, страница гео-блокирована | Яндекс.Музыка artist/25452123 + 3 альбома |
| след к копии | найден указатель на скачиваемый контент | YouTube watch?v=Gmn4xsjWigw → трек 03 |

**Сверка соответствий «название ↔ файл корпуса»:** порог Δ≤1 с (округление
ffprobe). Работает каскад: сначала сопоставление названий, затем сверка
длительностей, затем — только совпавшие переводятся в «подтверждено».
Хронология: первая сверка 7/7 (Apple Music), после audset — 45/49.
Команда-эталон: `scripts/audset_crosscheck.py` (сопоставление по
нормализованным названиям + светка длительностей, порог в коде).

**Измеренная ловушка каталогов-агрегаторов:** метаданные audset согласованы
с корпусом (45/49, Δ≤1 с), но файлы на их CDN НЕ совпадают с их же
метаданными (6/7 файлов, Δ 1.2–32.6 с). Правило: **метаданные — валидный
след, файлы — отдельный носитель, требующий контентной сверки.**

**Доказательство:** data/ruvson/audset_artist96195_report.json; коммит b835031.

## Фаза 5. Добор копий с audset: полная рабочая схема

Цепочка, отработанная на 7 файлах (все скачаны, верифицированы, 2 признаны
тем же взятием, что корпус; 03 закрыт):

```bash
# Шаг 1. Страница трека: https://audset.ru/track/<ID>
curl -s -m 15 "https://audset.ru/track/45934270" -H "User-Agent: Mozilla/5.0" -o t.html

# Шаг 2. Вытащить CDN-ссылку из HTML (волна-хосты wave*.audset.ru):
#   в HTML есть <... https://wave2.audset.ru/<hash>/<имя>.mp3 ...>

# Шаг 3. ПРОЦЕНТ-ЭНКОД URL обязательно — пробелы/юникод в пути рвут curl
#   (измерено: параллельная закачка с сырыми пробелами молча дала 0 файлов):
python3 -c "import urllib.parse; print(urllib.parse.quote(url, safe=':/'))"

# Шаг 4. Скачать и сразу два замера:
curl -s -m 120 -A "Mozilla/5.0" -o out.mp3 "<encoded_url>"
ffprobe -v error -show_entries format=duration,bit_rate -show_entries \
  stream=codec_name,sample_rate,channels -of json out.mp3   # длительность/формат
sha256sum out.mp3                                            # провенанс
# CDN отдаёт Content-Disposition: attachment — это прямое скачивание.

# Шаг 5. Контентная сверка с корпусом — ТОТ ЖЕ ЛИ ВЗЯТЬ (скрипт
# scripts/audset_content_check.py):
#   decode -> mono 16k -> per-second RMS конверты -> поиск сдвига кросс-
#   корреляцией -> ПИРСОН ВНУТРИ ПЕРЕКРЫТИЯ (пере-стандартизация),
#   минимальное перекрытие 45 с.
#   Вердикты: corr≥0.85 тот же взять; 0.5–0.85 та же песня другой мастер;
#   <0.5 разный материал.
```

**Ловушка №1 (ловилась реально):** первая версия сверки давала corr>1.0 —
корреляция без пере-стандартизации внутри перекрытия на коротких хвостах
даёт мусорные значения вплоть до >1. Фикс: Пирсон по перекрытию + min 45 с.

**Ловушка №2:** ffprobe-длительность mp3 может расходиться с метаданной
сайта-источника на десятки секунд — доверять только замеру файла.

**Результаты (все измерены):** audset-копии 01 (corr 0.974, offset 0) и 05
(corr 0.968, offset 0) — тот же взять, что корпус; «Не играй в любовь
(Remix)» CDN-файл ≠ 07 (0.395) и ≠ 48 (0.604, слабо) — чужая нарезка;
03 «Где настоящее» полная копия 243.57 с получена (track/45934270);
2 новых трека в руках: «То о чём молчим» 178.23 с, «Это не секрет» 202.29 с.

**Доказательство:** data/ruvson/audset_content_check.json,
audset_download_manifest.json; коммит b835031.

## Фаза 7. Проверка целостности: что реально ловит дефекты

1. **sha256 контейнера ≠ аудио.** Рабочая копия 01 расходилась с
   манифест-оригиналом на 1 байт — md5 декодированного PCM (s16le 44.1k
   stereo) совпал бит-в-бит: разница в теге контейнера, аудио идентично.
   Правило: **тег ≠ аудио; сомнение разрешается декодированием, не глазами.**
2. **Пересверка рабочих копий** (`scripts/ruvson_audio_resync.py`):
   52 файла → 48 EXTRACT_BITIDENTICAL, 2 TAG_ONLY_DIFF, 0 CONTENT_DIFF,
   2 сервисных копии вне манифеста задокументированы.
3. **Тест вайпом (проведён дважды):** после полного стирания raw-данных
   корпус восстановлен 50/50 бит-в-бит по манифесту из git. Принцип 4
   устава доказан практикой.

**Доказательство:** data/ruvson/audio_resync_report.json; коммит b6c5ed9.

  после пуша обязательная верификация `git ls-remote origin main` —
  API GitHub из песочницы ловит rate-limit, git-транспорт — нет.
- Параллельный журнал сессий — `/home/z/my-project/worklog.md`
  (Task ID, шаги, артефакты); репо и worklog переживают друг друга.
- Правило `git add`: **поимённо перечислять файлы** — `git add -A` на свежем
  клоне захватывает шум mode-прав (измерено, перезаписано коммитом).

## 2026-10-28 · Task 19-v2 · ОДИН голос RUVSON на 20 языках: ретейки sw/ko, приборный QC, релиз

**Результат:** релиз `one-voice-20langs-20261028` — 20 клипов по 10–11 с, голос один
(регистр всех клипов 240–259 Гц против цели 245 Гц = разброс 1.1 полутона), whisper-раундтрип
медиана 0.832 (en/fr 1.00, ja 0.98, tr 0.92, es 0.89, ru 0.88, ko 0.87, sw 0.85; слабые — только
4 языка вне XTTS: bn 0.17 / te 0.16 / vi 0.24 / mr 0.28 — фонетическая транслитерация, помечено).
Доказательство скачивания: анонимно `curl -L` → 200 OK, 11 939 467 байт zip / 4 769 480 байт mp3.

**Рецепт фикса bf16-инференса после перезапуска песочницы (главная ловушка):**
torch 2.14.1+cpu, XTTS-v2, ядро GPT в bf16. Симптомы шли цепочкой, каждый чинится на месте:

1. `conditioning_encoder` в bf16 + мел fp32 → `Input type (float) and bias type (c10::BFloat16)`.
   Фикс: `model.gpt.conditioning_encoder.to(torch.float32)` и `conditioning_perceiver` тоже.
2. LayerNorm: `mixed dtype (CPU): expect parameter to have scalar type of Float` — на этой сборке
   layer_norm с bf16-входом ТРЕБУЕТ fp32-параметры, но тогда Linear после него получает fp32.
   Фикс: обёртка `forward` у 62 LayerNorm ядра: `F.layer_norm(x.float(), ..., w, b, eps).to(torch.bfloat16)`
   (считаем в fp32, отдаём bf16). Perceiver/cond LN не трогать (у них путь fp32 целиком).
3. `wpe` (позиционный эмбеддинг transformers) отдаёт fp32 и промотирует вход блока: фикс —
   forward-pre-hook на каждый из 30 блоков, каст `hidden_states` к dtype ядра + каст
   `inputs_embeds` на входе трансформера.
4. hifigan fp32 получает латенты bf16: shim на `forward` — `lat.float(), g.float()`.
5. `return_latent=True` возвращает голый ТЕНЗОР (не tuple) bf16 → `.numpy()` падает:
