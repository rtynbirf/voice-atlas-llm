# Как вносить изменения

## Коротко о том, как устроен аккаунт

Это личный аккаунт `rtynbirf`; часть проектов ведут агенты по мандатам
Хозяина. Правила игры описаны в доктрине: `rtynbirf/repo-doctrine`.

## Правило аддитивности (главное)

- ✅ добавлять файлы, главы, флаги безопасности, темы — можно;
- ❌ удалять чужие файлы и переписывать чужие тексты без спроса — нельзя;
- ❌ force-push и переписывание истории — нельзя никогда, откат только `git revert`.

## Как предложить изменение

1. **Мелкая правка** (опечатка, ссылка, ясность): issue с описанием —
   внесём сами, так история чище.
2. **Изменение кода/документов**: форк → ветка → PR. Один PR — одна мысль.
3. **Существенная новая функциональность**: сначала issue с предложением,
   обсудим до кода, чтобы не делать лишнего.

## Формат коммитов

`тип(область): суть по-русски` — например:

```
feat(autopilot): выбор первого узла PAC-цепочки
fix(pac): BOM для PowerShell 5.1
docs: оглавление ранбука
```

Типы: `feat`, `fix`, `docs`, `chore`, `refactor`, `test`, `worklog`.

## Проверки перед отправкой

- в коде и текстах нет секретов (токены, ключи, пароли) — только плейсхолдеры;
- если правили PowerShell — файл сохранён с BOM (кириллица в PS 5.1);
- README/документация обновлены, если менялось поведение.

Спасибо за вклад!
